> **PRIMARY MANDATE: ACTION-ONLY FINE-TUNING (STAGE 2)**

## 1. System Architecture & Theoretical Foundations

### A. Parameter Partitioning
- **Frozen Parameters (8,797,933,808)**: The entire VLM backbone, Qwen/Cosmos visual encoder, and language model heads remain frozen at base weights throughout Action-Only training.
- **Trainable Parameters (2,280,592,386)**: Only the Trajectory Action Expert (Flow Matching transformer), Fourier waypoint embeddings, and action projection layers are updated.
- **Bypassing Stage 1**: In `sft_stage2_nav`, passing `model.stage1_vlm_checkpoint_path=$CKPT_DIR_A1` instructs the model loader to use the base A1-format weights directly, allowing Action-Only training without running Stage 1.

### B. Flow Matching vs. Diffusion
- **Continuous Normalizing Flows (CNF)**: Rather than discrete-step DDPM diffusion, Alpamayo 1.5 formulates trajectory prediction via **Flow Matching** with optimal transport (linear probability paths):
  $$x_t = (1 - (1 - \sigma_{\min})t) x_0 + t x_1, \quad t \in [0, 1]$$
  where $x_0 \sim \mathcal{N}(0, I)$ is Gaussian noise, $x_1$ is the clean ground-truth trajectory, and $\sigma_{\min} \approx 10^{-4}$.
- **Vector Field Regression**: The Action Expert predicts the velocity vector field $v_\theta(x_t, t, c)$ conditioned on context $c$:
  $$\mathcal{L}_{\text{FM}}(\theta) = \mathbb{E}_{t, x_0, x_1} \left[ \| v_\theta(x_t, t, c) - u_t(x_1 | x_0) \|^2 \right]$$
  where the optimal target field is $u_t(x_1 | x_0) \approx x_1 - x_0$.
- **Inference Integration**: Waypoint trajectories are generated by integrating the learned ordinary differential equation (ODE) $dx/dt = v_\theta(x_t, t, c)$ from $t=0$ to $t=1$ using numerical solvers (Euler or Midpoint).

### C. Conditioning Context & Five Manoeuvre Classes
- **Visual Inputs**: 4 cameras (front-wide 120°, front-tele 30°, cross-left 120°, cross-right 120°) $\times$ 4 historical frames ($t_0 - 0.3\,\text{s} \dots t_0$) = 16 images total per step.
- **Ego-History**: 1.6 s past ego-vehicle trajectory (16 steps at 10 Hz) with speed and yaw rate.
- **Five Manoeuvre Classes (`nav_maneuver`)**:
  In v4, navigation instructions are cleanly separated into 5 distinct classes, mapping to explicit natural language commands in `nav_text`:
  1. `STRAIGHT` $\rightarrow$ `"Continue straight"`
  2. `TURN_LEFT` $\rightarrow$ `"Turn left in 11m"` (or `"Turn left in 35m"`)
  3. `TURN_RIGHT` $\rightarrow$ `"Turn right in 11m"` (or `"Turn right in 35m"`)
  4. `SWERVE_LEFT` $\rightarrow$ `"Change lane left in 11m"` (or `"Change lane left in 6m"`)
  5. `SWERVE_RIGHT` $\rightarrow$ `"Change lane right in 11m"` (or `"Change lane right in 6m"`)
- **Junction Turns vs. Lateral Swerves**:
  - **Junction Turn**: Strictly defined by map topology — the manoeuvre apex must lie inside an intersection surface (`MapLayer.INTERSECTION`).
  - **Swerve / Lateral Manoeuvre**: A mapped lane departure outside a junction (e.g. overtaking a construction obstacle, parked car, or lane merge). In a bypass, two distinct manoeuvres are generated: swerve out and merge back.
- **KV Cache Reuse**: The frozen VLM processes the visual, ego, and text prompt to generate key-value (KV) representations. The Action Expert cross-attends to this KV context to predict the next **6.4 s trajectory (64 waypoints at 10 Hz)** in the ego frame.

### D. Checkpoint Format Duality
- **Training Format (`alpamayo_r1`)**: SFT training runs on `alpamayo_r1`.
- **Inference / Serving Format (`alpamayo1_5`)**: FlashDrive inference runs on `alpamayo1_5` and expects `nav_text`.
- **Workflow Pipeline**:
  ```
  [Raw Released Alpamayo-1.5-10B]
          │
          ▼  Step 1: convert_checkpoint.py to-a1
  [Alpamayo-1.5-10B-A1-format]
          │
          ▼  Step 2: Train Action Expert ONLY (sft_stage2_nav, VLM frozen)
  [output_stage2_lead_v4/checkpoint-XXXX] (format: alpamayo_r1)
          │
          ▼  Step 3: convert_checkpoint.py to-a15  <-- MANDATORY STEP
  [Alpamayo-1.5-10B-Lead-Large-v4-A15] (format: alpamayo1_5)
          │
          ▼  Step 4: Symlink-Safe Package & Deploy to FlashDrive
  ```
  *If you omit Step 3, `flashdrive_server.py` crashes with: `TypeError: create_message() got unexpected keyword argument 'nav_text'`!*

## 2. Dataset: Curated LEAD Dataset v4 (`lead-alpamayo-pai_large_v4`)

The dataset is hosted at `earth37815/lead-alpamayo-pai_large_v4` on Hugging Face (~72 GB across 29 chunks: `chunk_0000` to `chunk_0028`). It represents the complete 646-route multi-rig collection across 41 CARLA scenario types in 11 towns (Town01–07, Town10HD, Town12, Town13, Town15).

### Dataset Statistics:
| Split | Routes / Clips (Curated) | Curated Nav Samples | Straight | Junction Left / Right | Swerve Left / Right | Raw 0.4s Samples (`*_all.json`) |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **train** | 601 / 1,694 | **16,040** | 8,020 | 2,005 / 2,005 | 2,005 / 2,005 | 42,836 |
| **val** | 45 / 146 | **1,720** | 860 | 215 / 215 | 215 / 215 | 3,736 |
| **total** | **646 / 1,840** | **17,760** | **8,880** | **2,220 / 2,220** | **2,220 / 2,220** | **46,572** |

### Key Characteristics of v4:
1. **Balanced Manoeuvre Mix**: Exactly 50.0% straight and 12.5% in each of the four lateral classes (`TURN_LEFT`, `TURN_RIGHT`, `SWERVE_LEFT`, `SWERVE_RIGHT` in strict 1:1:1:1 balance), eliminating v3's 3:1 left-swerve bias.
2. **Fine-Grained 0.4s Stride**: Samples are drawn every 0.4 s instead of 1.0 s, providing 2.5× more training samples (17,760 total) while ensuring disjoint 4-frame camera stacks ($t_0 - 0.3\,\text{s} \dots t_0$).
3. **Bottleneck / Binding Constraint**: `SWERVE_RIGHT` is the scarcest verified class (2,005 in train, 215 in val), setting the quota for all lateral classes and straight driving ($4 \times 2,005 = 8,020$).
4. **Low Stationary Fraction**: Capped well below 10%, landing at **1.7% train / 0.5% val** (~1.6% overall), since moving samples fill quotas first.
5. **Driven-Path Verification**: Every sample is verified against the executed vehicle trajectory (`turn_check == "ok"`). Contradicted and unjudged samples are eliminated.

> [!IMPORTANT]
> **Always pass `chunk_ids=null`** for both `data.train_dataset` and `data.val_dataset`. The default recipe hardcodes NVIDIA's 19 demo chunks (e.g. `[214, 224, ...]`), which will fail on LEAD data. Setting `chunk_ids=null` enables the loader to process the full curated annotation JSON.

## 5. Training Path A: Action-Only Fine-Tuning (Stage 2 - Recommended)

This mode directly trains the 2.28B Trajectory Action Expert while keeping the 8.8B VLM backbone completely frozen (`cotrain_vlm: false`).

### Step Arithmetic:
- **Dataset Size**: **16,040** curated training samples.
- **Single-GPU (1× A100-SXM4-80GB)**:
  - Batch size per GPU: 1
  - Gradient accumulation steps: 8 (Effective batch size = 8)
  - Optimizer steps per epoch: $16,040 / 8 = \mathbf{2,005 \text{ steps/epoch}}$
  - **Full Schedule (10 Epochs)**: $2,005 \times 10 = \mathbf{20,050 \text{ steps}}$
  - **Medium Schedule (5 Epochs)**: $2,005 \times 5 = \mathbf{10,025 \text{ steps}}$
  - **Fast Screening (3 Epochs)**: $2,005 \times 3 = \mathbf{6,015 \text{ steps}}$
  - Warmup: 200 steps
  - Checkpoint saving: Every 400 steps (or 1,000 steps, `save_total_limit=5`)
- **Multi-GPU (8× A100 / H100)**:
  - Batch size per GPU: 1 $\times$ 8 GPUs = 8 per step
  - Gradient accumulation steps: 1 (Effective batch size = 8)
  - Steps per epoch: 2,005 steps/epoch
  - **10 Epochs Total**: **20,050 steps** (~11.2 hours on 8× A100 SXM4)

> [!WARNING]
> **Container Shared Memory Safeguard (`/dev/shm`)**:
> In standard Docker or cloud environments where `/dev/shm` is 64 MB, setting `dataloader_num_workers > 0` causes PyTorch IPC shared memory exhaustion and crashes with `Bus error`. You **must** keep `dataloader_num_workers=0`, `dataloader_pin_memory=false`, and `dataloader_prefetch_factor=null`.

> [!IMPORTANT]
> **Lossless Crash Resilience & Container RAM Budget**:
> - **Storage**: Disk storage has 12 TB free (`/workspace`), easily accommodating full checkpoint archives (~30 GB each).
> - **Container Memory Budget**: The container enforces a 32.0 GB cgroup memory limit (`/sys/fs/cgroup/memory/memory.limit_in_bytes = 34359738368`).
> - **The Safeguards**:
>   1. **`performance.zip_cache=false` (MANDATORY)**: Stream clips directly from NVMe SSD on-the-fly, keeping dataset RAM flat under **~1.5 GB** (preventing the 25+ GB memory leak of in-RAM frame caching).
>   2. **`trainer.save_only_model=false` (MANDATORY FOR CRASH RESILIENCE)**: Always dump `optimizer.pt` (8.5 GB AdamW momentum/variance states) and `scheduler.pt` alongside the model weights. Because `zip_cache=false` maintains system RAM at ~1.5 GB, serializing the 8.5 GB optimizer state stays comfortably under the 32 GB ceiling (~12-14 GB peak). This ensures training can be resumed 100% losslessly after sudden power cuts or container restarts.
>   3. **Garbage Collection & Cache Purge**: Invoke `gc.collect()` and `torch.cuda.empty_cache()` inside [`performance/ema_callback.py`](file:///workspace/alpamayo-recipes/recipes/alpamayo1_5_sft/performance/ema_callback.py) before/after checkpoint writes.

## 7. Training & Inference Improvements

### A. Raw (Non-EMA) vs. EMA Checkpoints
- In closed-loop CARLA benchmarking, the **active (Non-EMA) weights** consistently outperformed EMA smoothed weights (**72.2 DS vs. 58.2 DS**).
- **The Diagnosis**: While EMA helps stability in multi-agent encounters, high EMA smoothing ($\beta = 0.999$) acts as a low-pass filter that dampens peak curvature on high-speed curves (Highway Exit 23687) and reduces heading realignment when pulling away from dead stops (Pedestrian Crossing 14194).
- **Recommendation**: Deploy the Non-EMA checkpoint first for evaluation, or use low EMA decay ($\beta = 0.99$).

### B. Scaling to the 646-Route v4 Dataset
- The v4 dataset directly addresses the manoeuvre skew identified in earlier releases:
  - **Balanced Overtaking & Lane Maneuvers**: Balanced 2,005 left swerves and 2,005 right swerves in train, removing the previous 3:1 left-swerve bias.
  - **Symmetric Turning & Straight Balance**: Strict 1:1:1:1 lateral balance (2,005 each of `TURN_LEFT`, `TURN_RIGHT`, `SWERVE_LEFT`, `SWERVE_RIGHT`) and 8,020 `STRAIGHT` samples (50.0%).
  - **Signalized Intersections & Complex Scenarios**: Retains comprehensive coverage of all 41 CARLA scenario types across 11 towns.

### C. Inference ODE Solver Steps & Candidate Sampling
- **Euler Steps**: At inference, default solvers use $N=5$ Euler integration steps for speed. Increasing to $N=10$ or $N=20$ steps reduces ODE approximation error and generates smoother trajectory curvature.
- **Candidate Trajectory Generation ($K$ Samples)**: Sample $K \in \{5, 10\}$ trajectories from different Gaussian noise initializations $x_0^{(k)} \sim \mathcal{N}(0, I)$, and rank them using the VLM critique score or distance to navigation centerline.

## 9. Symlink-Safe Packaging & Deployment

`convert_checkpoint.py` creates symbolic links to weight files. To deploy to remote servers or containers without broken links, package the directory by dereferencing symlinks into real files:

```bash
# Option A: Standalone tarball (dereferences symlinks to real files)
cd $YOUR_HOME
tar -chzf stage2_lead_v4_checkpoint_a15.tar.gz -C $YOUR_HOME $(basename $CKPT_DIR_A15)

# Option B: Standalone zip via Python zipfile (dereferences symlinks)
python3 -c "
import os, zipfile
src = '$CKPT_DIR_A15'
dst = '$YOUR_HOME/stage2_lead_v4_checkpoint_a15.zip'
print(f'Archiving {src} -> {dst} (dereferencing symlinks)...')
with zipfile.ZipFile(dst, 'w', compression=zipfile.ZIP_DEFLATED) as zf:
    for root, _, files in os.walk(src, followlinks=True):
        for f in files:
            full = os.path.join(root, f)
            rel = os.path.relpath(full, src)
            zf.write(full, rel)
print('Done!')
"
```

```python
import inspect

def safe_create_message(create_message_fn, frames, nav_text=None, **kwargs):
    """Adaptively call create_message whether or not the underlying package supports nav_text."""
    sig = inspect.signature(create_message_fn)
    params = sig.parameters

    call_kwargs = {}
    if "frames" in params:
        call_kwargs["frames"] = frames
    elif "images" in params:
        call_kwargs["images"] = frames
    else:
        return (
            create_message_fn(frames, nav_text=nav_text)
            if "nav_text" in params
            else create_message_fn(frames)
        )

    accepts_kwargs = any(p.kind == inspect.Parameter.VAR_KEYWORD for p in params.values())
    if "nav_text" in params or accepts_kwargs:
        if nav_text is not None:
            call_kwargs["nav_text"] = nav_text

    return create_message_fn(**call_kwargs)
```

## 13. Downtime & Disconnect Prevention Protocol (IMPORTANT: Terminal & Web Agent Immunity)

> [!IMPORTANT]
> **CRITICAL PRECAUTION: RUNTIME IMMUNITY & OOM QUARANTINE (MANDATORY)**  
> Long-running training jobs executed inside cloud environments and AI agents (such as Antigravity) will terminate abruptly if launched inside an interactive shell or standard agent background task. To guarantee uninterrupted execution:
> 1. **Always Use True Double-Fork Daemonization**: Detach the job completely so it is adopted directly by **`init` (`PPID: 1`)** with no controlling terminal (`TTY: ?`). This guarantees complete immunity against browser closures, Wi-Fi drops, and `agy` agent daemon restarts.
> 2. **Never Run Compression During Active Training**: The container enforces a strict **32 GB RAM ceiling** (`/sys/fs/cgroup/memory/memory.limit_in_bytes = 34,359,738,368`). Running heavy 21 GB `tar` or `zip` compression while PyTorch is checkpointing exhausts page cache and triggers the Linux kernel's uncatchable `SIGKILL` (OOM kill). Always run archive packaging with parallel `pigz` after training completes.

### A. Root Cause Analysis (Why Training Stops on Web Disconnects)
When executing deep model fine-tuning runs lasting hours inside cloud environments and AI agents (such as Antigravity), runs frequently get terminated by three distinct failure modes:
1. **Interactive Shell Coupling (`pts`)**: Interactive terminals create a pseudo-terminal (`pts/1`) tied to the web session. When your browser closes, Wi-Fi drops, or the web proxy refreshes, the controlling terminal terminates.
2. **Antigravity CLI Daemon Restarts**: The `agy` agent runs in a controlling shell. When `agy` undergoes a session restart (e.g. `[Notice] All your subagents and background tasks have been stopped due to server restart`), it sends termination signals to all its child processes and background tasks.
3. **Container Cgroup 32 GB RAM Exhaustion (OOM Killer)**: The container environment enforces a strict 32.0 GB memory limit (`/sys/fs/cgroup/memory/memory.limit_in_bytes = 34,359,738,368`). Running heavy 21 GB compression (`tar -chzf`) concurrently with active PyTorch training and checkpoint serialization (which dumps 30 GB of safetensors and 8.5 GB AdamW state) exhausts dirty page cache and heap, triggering the kernel's uncatchable `SIGKILL` (OOM kill).

---

### B. The 4 Technical Defenses for 100% Immunity

#### 1. True Double-Fork Daemonization (Adoption by Init PID 1)
Standard backgrounding (`nohup ... &`) still keeps the process in the shell's process hierarchy. The gold standard for complete immunity is **Double-Fork Daemonization** with `os.setsid()`:
- **First Fork**: Intermediate parent exits immediately.
- **Session Decoupling (`setsid`)**: The child detaches from the controlling pseudo-terminal (`TTY: ?`), creating its own session.
- **Second Fork**: Creates a grandchild process that is not a session leader (cannot acquire a controlling terminal).
- **Adoption by PID 1**: The grandchild is adopted directly by `init` (`PPID: 1`). When the browser closes or `agy` restarts, the Linux kernel leaves PID 1's adopted processes completely untouched.
- **Standard I/O Redirection**: `stdin` is redirected to `/dev/null`, and `stdout`/`stderr` append directly to the log file on disk.

```python
# Double-Forking Daemon Architecture
pid = os.fork()
if pid > 0: sys.exit(0)
os.setsid()
pid2 = os.fork()
if pid2 > 0: sys.exit(0)
# Child is now owned by PID 1 with no controlling TTY
```

#### 2. Signal Immunity via `trap '' HUP TERM`
Adding signal immunity masks `SIGHUP` and `SIGTERM` as `SIG_IGN` (Ignore) at the operating system kernel level:
```bash
trap '' HUP TERM
```
When a terminal session drops, the Linux kernel discards the hangup signal instead of terminating the training process.

#### 3. High-Frequency Checkpointing (`save_steps: 50`)
- **Risk of Large Intervals**: At `save_steps: 200` (or `400`), an unexpected halt rolls back up to **40 minutes** of compute.
- **Safety with 50 Steps**: Setting `save_steps: 50` guarantees a lossless Adam momentum and weight save every **~10 minutes**.
- **Disk Footprint**: In combination with `save_total_limit: 5`, older checkpoints are pruned automatically, using ~50 GB out of available TBs of disk space.

#### 4. I/O and RAM Quarantine (Preventing Cgroup OOM)
- **Sequential Execution**: Never run heavy 21 GB compression jobs (`tar` or `zip`) in parallel with active PyTorch training. Wait for training to complete before running archive compression.
- **Parallel Multi-Core Compression (`pigz`)**: When packaging converted checkpoints, always use parallel `pigz` across CPU cores (`tar --use-compress-program=pigz -chf ...`), which finishes in ~1.5 minutes rather than choking disk I/O and page cache for 25+ minutes.

### C. Self-Healing Auto-Resume Loop

To ensure true overnight autonomy, wrap execution in a persistent self-healing supervisor loop that checks for the final deployment archive:
```python
#!/usr/bin/env python3
import os, sys, time, signal, subprocess

TARGET_ARCHIVE = "/workspace/Alpamayo-1.5-10B-Lead-Large-v4-A15.tar.gz"
LOG_FILE = "/workspace/train_stage2_v4.log"

def run_loop():
    signal.signal(signal.SIGHUP, signal.SIG_IGN)
    signal.signal(signal.SIGTERM, signal.SIG_IGN)

    while not os.path.exists(TARGET_ARCHIVE):
        with open(LOG_FILE, "a") as out:
            proc = subprocess.Popen(
                ["/workspace/launch_stage2_v4.sh"],
                stdout=out, stderr=subprocess.STDOUT, stdin=subprocess.DEVNULL,
                start_new_session=True, cwd="/workspace"
            )
            proc.wait()

        if os.path.exists(TARGET_ARCHIVE):
            break
        time.sleep(10)

def main():
    if os.fork() > 0: sys.exit(0)
    os.setsid()
    if os.fork() > 0: sys.exit(0)
    devnull = os.open(os.devnull, os.O_RDWR)
    os.dup2(devnull, sys.stdin.fileno())
    run_loop()

if __name__ == "__main__":
    main()
```
